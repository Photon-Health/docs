Most integrations start in the frontend with one Embed component, then move work to the backend as they grow. Each step below builds on the one before it, and the prescriber always signs and sends in Embed.

| | Integration | Your frontend | Your backend | The prescriber |
| --- | --- | --- | --- | --- |
| 1 | [Prescribe embed](/integrations/prescribe-embed) | Renders `PhotonOrder` with your patient | Nothing | Picks drugs, signs, sends |
| 2 | [Sync patients](/integrations/sync-patients) | Passes the patient's Photon id | Keeps patients, allergies and medications up to date | Picks drugs, signs, sends |
| 3 | [One-click orders](/integrations/one-click-orders) | Opens the drafted order by id | Drafts the order from templates using your own rules | Reviews, signs, sends |
| 4 | [Agent-drafted orders](/integrations/agent-drafted-orders) | Opens the agent's draft | An agent takes intake and drafts prescriptions over MCP | Reviews, signs, sends |

## Which Embed?

Every guide uses the React component. If your frontend isn't React, use the [iframe](/embed/iframe) instead. It takes the same records in its URL.
