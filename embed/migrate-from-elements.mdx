Photon Elements (`@photonhealth/elements`, with `<photon-client>` and `<photon-prescribe-workflow>`) is deprecated. Embed replaces it. It covers the same prescribing workflow, runs on the [Network API](/network/overview), and lets the patient choose their pharmacy by default.

Most migrations change one component. Patients you synced before keep their `pat_…` ids.

## 1. Choose how to embed

| Your frontend | Use |
| --- | --- |
| React | Embed's [React components](/embed/react) |
| Angular, Vue, or anything else | Embed's [iframe](/embed/iframe). It needs no package or credentials. |
| A link from another tool | An [app link](/embed/links), which replaces the `/prescriptions/new` deep link |

## 2. Replace the client

<CodeGroup>

```html Before
<photon-client id="YOUR_CLIENT_ID" org="YOUR_ORG_ID" dev-mode="true" redirect-uri="https://example.com">
  <photon-prescribe-workflow patient-id="pat_01M3WQQHRB1T0K1469KD18BAWX" />
</photon-client>
```

```tsx After
<PhotonProvider clientId="YOUR_CLIENT_ID" organization="YOUR_ORG_ID" environment="neutron">
  <PhotonOrder patient="pat_01M3WQQHRB1T0K1469KD18BAWX" />
</PhotonProvider>
```

</CodeGroup>

| `<photon-client>` | Embed |
| --- | --- |
| `id` | `clientId`. It's the same Application credential. |
| `org` | `organization` |
| `dev-mode="true"` | `environment="neutron"`. Embed defaults to production. |
| `redirect-uri`, `redirect-path` | Not needed. Sign-in returns to the page it started on. |
| `auto-login` | Not needed. Embed signs in on its own when it can, and otherwise shows **Sign in to Photon**. |

The iframe takes no client at all. It signs the prescriber in to Photon itself.

## 3. Replace the workflow

`<photon-prescribe-workflow>` becomes `<PhotonOrder>`. In an iframe, it becomes `/order/embed`.

| `<photon-prescribe-workflow>` | Embed |
| --- | --- |
| `patient-id` | `patient="pat_…"`, or `?patient=pat_…` in an iframe. Embed takes Photon ids only. To pass your own patient, give their details (`patient={{ demographic: { … } }}`) and Photon matches them. |
| `template-ids` | `order={{ patient: { id }, prescriptions: { add: [{ templateId: "…" }] } }}` |
| `prescription-ids` | `order={{ prescriptions: { add: [{ id: "rx_…" }] } }}`. Embed puts the draft itself on the order rather than copying it. |
| `initial-prescriptions`, `template-overrides`, `prescription-overrides` | Draft the prescriptions from your backend with the values you want ([prescription sync](/network/prescription)), then pass their ids. See [One-click orders](/integrations/one-click-orders). |
| `enable-order`, `enable-send-to-patient` | Always on. **Send** texts the patient, who chooses their pharmacy. |
| `pharmacy-id` | Set the pharmacy on the draft order from your backend ([`pharmacy`](/network/order#pharmacies)), then open the order by id |
| `external-order-id` | Set `externalId` on the order from your backend |
| `hide-patient-card` | `fixed` keeps the patient visible but removes **Change patient** |

### Events

| Elements event | Embed |
| --- | --- |
| `photon-order-created` | `onSent(order)`, or the `PhotonOrder.onSent` message from an iframe |
| `photon-prescriptions-created` | `onPrescription(rx)` on each prescription, or `onOrder(order)` for all of them |
| `photon-draft-prescription-created` | `onOrder(order)`, which fires as lines are saved |
| `photon-prescriptions-error`, `photon-order-error` | No event. The card shows the error to the prescriber. |

Embed events pass the live object: `order.id` and `order.state`. They don't pass a raw GraphQL payload. For what happens after sending, use [webhooks](/network/webhooks). They haven't changed.

## 4. Replace deep links

| Before | After |
| --- | --- |
| `app.neutron.health/prescriptions/new?patientId=pat_…` | `rx.neutron.health/order?patient=pat_…` |
| `…&templateIds=tmp_…` | Build the link with `ph.order.url({ patient: { id }, prescriptions: { add: [{ templateId }] } })`. See [App links](/embed/links). |

## Not in Embed yet

These Elements features don't have an Embed equivalent yet. If you rely on one, talk to your Photon contact before you migrate.

- Prescriber-chosen pharmacy in the UI: `enable-local-pickup`, `enable-delivery-pharmacies` and `mail-order-ids`. Your backend can still set the pharmacy on a draft order.
- Catalog limits: `disable-list` and `allow-off-catalog-search`
- Coverage checks: `enable-coverage-check`. Benefits are coming to Embed as pharmacy offers.
- Patient context in the workflow: `weight`, `weight-unit`, `address`, and the `supervisor` for an order
- `additional-notes`, `hide-templates` and `hide-submit`
- Recent prescriptions: `<photon-med-history>`, `enable-med-history*` and `enable-combine-and-duplicate`
- Opening a patient by your own external id
