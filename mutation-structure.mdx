---
title: "Mutation Structure"
---

There are 3 mutations that follow the same structure in this API. Those mutations are patient, prescription, and order. These are the entry points for a prescription workflow and map directly to specific actions. 

```graphql
type Mutation {
  patient(patient: PatientInput, metadata: RequestMetadata!): PatientResult!

  prescription(prescription: PrescriptionInput, metadata: RequestMetadata!): PrescriptionResult!

  order(input: OrderInput!, metadata: RequestMetadata!): OrderResult!
}
```

Each mutation is structured in the same manner: 

#### **Arguments**

1. Mutation Input 
2. metadata

#### Return Types

1. Mutation Payload - business outcome with applied/unapplied changes 
2. Ambiguous Match - ambiguous match type. Nothing was written 
3. UnauthorizedError - the caller lacks permission for this action (a missing or invalid token returns a top-level error instead)
4. UpstreamServiceError - a downstream service failed

```graphql
mutation Patient($patient: PatientInput, $metadata: RequestMetadata!) {
  patient(patient: $patient, metadata: $metadata) {
    __typename
    ... on PatientPayload {
      patient {
        __typename
        ... on Patient { id }
        ... on UpstreamServiceError { code message service retryable }
      }
      appliedChanges { key label status severity reason }
      unappliedChanges {
        key
        label
        status
        severity
        reason
        options { displayName argument value }
      }
    }
    ... on AmbiguousPatientMatch {
      reason
      candidates { id firstName lastName dateOfBirth }
    }
    ... on UnauthorizedError { code message requiredPermission }
    ... on UpstreamServiceError { code message service retryable }
  }
}
```

The mutation input argument is the only field that largely differs between the mutations as each mutation requires specific details. 

For example, PatientInput accepts clinical, demographic, and ID details (all optional). Whereas OrderInput accepts order, patient, pharmacy, prescriptions, and state. You can see this in the full API reference.
