---
title: "Prescription Mutation"
description: "Draft a prescription, iterate on it, review screening alerts, and sign it with content-hash attestation."
---

The `prescription` mutation manages a prescription's full draft lifecycle: create a draft, update it, review clinical screening, and sign. It's the same mutation throughout — call it repeatedly with the same `id` to iterate until the draft is signed.

Prescriptions are kept separate from orders because the clinical and logistical concerns are distinct: a prescription is drafted, screened, and signed _before_ it's routed anywhere. That separation also supports writing prescriptions ahead of time, or bundling several into one order later.

## Create > Retrieve > Change > Sign

1. **Create a prescription:** Send a patient, drug, dosing instructions and dispense details without an `id` to create an unsigned draft, which is automatically checked for safety problems.
2. **Retrieve a prescription:** Send only the prescription's `id` to get back its stored details, safety alerts and current signing status.
3. **Change a prescription:** Send the prescription's `id` with only the fields to change; changing a signed prescription invalidates its signature.
4. **Sign a prescription:** Send the `contentHash` from the latest retrieve or change response back as `signedHash` to sign the prescription; this requires the `write:prescription` permission.

<CodeGroup>

```graphql Mutation
mutation Prescription($prescription: PrescriptionInput!, $metadata: RequestMetadata!) {
  prescription(prescription: $prescription, metadata: $metadata) {
    __typename
    ... on PrescriptionPayload {
      prescription {
        id
        status
        patient { id }
        templateId
        treatment { id name rxNormId ndc upc }
        instructions
        dispense { quantity unit daysSupply refillsAllowed dispenseAsWritten }
        clinical {
          diagnoses { id name icd10Code }
          notes
        }
        screeningAlerts {
          severity
          type
          category
          description
          involvedEntities { id name }
          options { ...OptionFields }
        }
        signing { state contentHash message signedAt }
      }
      appliedChanges { ...ChangeFields }
      unappliedChanges { ...ChangeFields }
    }
    ... on AmbiguousPrescriptionMatch {
      reason
      candidates {
        id
        instructions
        dispense { quantity unit daysSupply refillsAllowed }
      }
    }
    ... on UnauthorizedError { code message requiredPermission }
    ... on UpstreamServiceError { code message service retryable }
  }
}

# Fields shared by every Change, applied or not.
fragment ChangeFields on Change {
  key
  label
  status
  severity
  category
  operation
  reason
  options { ...OptionFields }
  detail {
    __typename
    ... on FieldChangeDetail { previousValue { displayValue } newValue { displayValue } }
    ... on EntityResolutionDetail { inputText resolvedEntityId }
  }
}

# A suggested next action, e.g. a candidate to pick when a match is AMBIGUOUS.
fragment OptionFields on ChangeOption {
  displayName
  reason
  operation
  argument
  value
  match { matchType confidence }
}
```
