The `patient` mutation is the entry point for all patient data in Photon Rx. One call can create a patient, update an existing one, and modify clinical history — allergies, medications, diagnoses, and benefits.

## Create a patient

Send a patient's details and optional clinical information without an `id`, and the API creates a new record, or returns the existing patient if the details match one exactly.

<CodeGroup>

```graphql Mutation
mutation Patient($patient: PatientInput!, $metadata: RequestMetadata!) {
  patient(patient: $patient, metadata: $metadata) {
    __typename
    ... on PatientPayload {
      patient {
        __typename
        ... on Patient {
          id
          demographic {
            name { first last }
            dateOfBirth
            sex
            email
            phone
            address { street1 street2 city state postalCode country }
            benefits { id bin pcn groupId memberId }
          }
          clinical {
            allergies { id name rxNormId }
            medications { id name rxNormId status }
            diagnoses { id name icd10Code }
          }
        }
        ... on UpstreamServiceError { code message service retryable }
      }
      appliedChanges {
        key
        label
        status
        severity
        category
        reason
        detail {
          __typename
          ... on EntityResolutionDetail { inputText resolvedEntityId }
        }
      }
      unappliedChanges {
        key
        label
        status
        severity
        category
        reason
        options { displayName operation argument value }
      }
    }
    ... on AmbiguousPatientMatch {
      reason
      candidates { id firstName lastName dateOfBirth }
    }
    ... on UnauthorizedError { code message requiredPermission }
    ... on UpstreamServiceError { code message service retryable }
  }
}
```

## Retrieve a patient

Send only the patient's `id` to get back the full record, including details, insurance, allergies, medications and diagnoses.

<CodeGroup>

```graphql Mutation
mutation Patient($patient: PatientInput!, $metadata: RequestMetadata!) {
  patient(patient: $patient, metadata: $metadata) {
    __typename
    ... on PatientPayload {
      patient {
        __typename
        ... on Patient {
          id
          demographic {
            name { first middle last }
            dateOfBirth
            sex
            gender
            email
            phone
            address { street1 street2 city state postalCode country }
            benefits { id bin pcn groupId memberId }
            preferredPharmacy { id name }
          }
          clinical {
            allergies { id name rxNormId }
            medications { id name rxNormId status }
            diagnoses { id name icd10Code }
          }
        }
        ... on UpstreamServiceError { code message service retryable }
      }
      unappliedChanges { key label status severity reason }
    }
    ... on UnauthorizedError { code message requiredPermission }
    ... on UpstreamServiceError { code message service retryable }
  }
}
```

```json Variables
{
  "patient": { "id": "pat_01EXAMPLEPATIENT000000000" },
  "metadata": { "source": "DIRECT_API", "client": "docs-example", "requestId": "req_0002" }
}
```

</CodeGroup>

## Change patient information

Send the patient's `id` with only the fields to change, using `add`, `remove` and `update` for lists like allergies, medications and insurance.

<CodeGroup>

```graphql Mutation
mutation Patient($patient: PatientInput!, $metadata: RequestMetadata!) {
  patient(patient: $patient, metadata: $metadata) {
    __typename
    ... on PatientPayload {
      patient {
        __typename
        ... on Patient {
          id
          demographic {
            address { street1 street2 city state postalCode country }
            benefits { id bin pcn groupId memberId }
            preferredPharmacy { id name }
          }
          clinical {
            allergies { id name rxNormId }
            medications { id name rxNormId status }
          }
        }
        ... on UpstreamServiceError { code message service retryable }
      }
      appliedChanges {
        key
        label
        status
        operation
        detail {
          __typename
          ... on FieldChangeDetail { previousValue { displayValue } newValue { displayValue } }
          ... on EntityResolutionDetail { inputText resolvedEntityId }
          ... on PharmacyResolutionDetail { inputText resolvedEntityId }
        }
      }
      unappliedChanges {
        key
        label
        status
        severity
        category
        reason
        options { displayName operation argument value }
      }
    }
    ... on UnauthorizedError { code message requiredPermission }
    ... on UpstreamServiceError { code message service retryable }
  }
}
```
