---
title: "Prescription Mutation Breakdown"
description: "Create or update a prescription draft, attach treatment and dispense details, and sign the prescription for submission to a pharmacy."
---

The `prescription` mutation lets you create new prescription drafts, update existing ones, and cryptographically sign them for submission. You can reference a patient by Photon ID or by demographic data, point to a treatment using an RxNorm ID or NDC, and specify dispense quantities and refill counts in a single call. When you supply an `id`, the mutation updates that draft; when you omit it, a new draft is created. Clinical screening alerts are evaluated on every write and surfaced in the response so you can gate signing on any warnings or blocks.

<Note>
  You cannot combine signing fields (`signing.signedHash`) with treatment or clinical edits in the same mutation call. First update the prescription's treatment and clinical data, then send a separate call containing only the `signing` input. This ensures the content hash you sign reflects the exact state of the record at signing time.
</Note>

## Mutation Signature

```graphql
mutation Prescription($prescription: PrescriptionInput, $metadata: RequestMetadata!) {
  prescription(prescription: $prescription, metadata: $metadata) {
    ... on PrescriptionPayload {
      prescription {
        id
        status
        screeningAlerts { severity type description }
        signing { state contentHash message signedAt }
      }
      appliedChanges { key status severity reason }
      unappliedChanges { key status severity reason }
    }
    ... on AmbiguousPrescriptionMatch {
      candidates { id instructions dispense { quantity unit } }
      reason
    }
    ... on UnauthorizedError {
      code
      message
      requiredPermission
    }
    ... on UpstreamServiceError {
      code
      message
      service
      retryable
    }
  }
}
```

## Arguments

<ParamField body="prescription" type="PrescriptionInput">
  The prescription data to create or update. Omitting it is rejected (`patient` and `treatment` are required).
</ParamField>

<ParamField body="metadata" type="RequestMetadata!" required>
  Request-level metadata used for audit logging and tracing. Required on every call.

  <Expandable title="RequestMetadata fields">
    <ParamField body="source" type="RequestSource!" required>
      The originating surface of this request. One of `WEB_APP`, `EMBEDDABLE_COMPONENT`, `DIRECT_API`, `MCP_CONNECTOR`, or `LLM_AGENT`.
    </ParamField>
    <ParamField body="sourceVersion" type="String">
      Version of the originating client (e.g., `"2.4.1"`).
    </ParamField>
    <ParamField body="client" type="String">
      Human-readable name of the calling application (e.g., `"AcmePractice EHR"`).
    </ParamField>
    <ParamField body="requestId" type="String">
      Idempotency key. Retrying with the same `requestId` returns the original result without re-applying changes.
    </ParamField>
  </Expandable>
</ParamField>

## PrescriptionInput Fields

<ParamField body="id" type="ID">
  The Photon ID of an existing draft prescription to update. Omit this field to create a new draft — if the patient already has an in-progress draft, that draft is updated instead.
</ParamField>

<ParamField body="patient" type="PatientReferenceInput">
  The patient this prescription is written for. You can reference an existing Photon patient by `id`, or supply demographic data to look up or create the patient inline.

  <Expandable title="PatientReferenceInput fields">
    <ParamField body="id" type="ID">
      Photon patient ID. Use this when the patient record already exists.
    </ParamField>
    <ParamField body="demographic" type="PatientDemographicInput">
      Demographic data for an inline patient lookup or creation. See the [patient mutation](/api/patient) for the full field reference.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="templateId" type="ID">
  The ID of an order-set template to base this prescription on. When supplied, the template pre-populates treatment, dispense, and clinical defaults that you can then override with other fields in this input.
</ParamField>

<ParamField body="treatment" type="TreatmentReferenceInput">
  The drug or treatment being prescribed. Provide at least one identifier — Photon `id`, `rxNormId`, `ndc`, or `upc`.

  <Expandable title="TreatmentReferenceInput fields">
    <ParamField body="id" type="ID">
      Photon internal treatment ID.
    </ParamField>
    <ParamField body="rxNormId" type="String">
      RxNorm concept unique identifier (RxCUI) for the treatment.
    </ParamField>
    <ParamField body="name" type="String">
      Human-readable drug name used for display and fallback matching.
    </ParamField>
    <ParamField body="ndc" type="String">
      National Drug Code (NDC) in 10- or 11-digit format.
    </ParamField>
    <ParamField body="upc" type="String">
      Universal Product Code for OTC or compound treatments.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="instructions" type="String">
  Patient-facing sig (directions for use), such as `"Take 1 tablet by mouth twice daily with food"`. Displayed on the prescription label by the dispensing pharmacy.
</ParamField>

<ParamField body="dispense" type="DispenseInput">
  Dispensing details for this prescription.

  <Expandable title="DispenseInput fields">
    <ParamField body="quantity" type="Float">
      The numeric quantity to dispense (e.g., `30.0` for 30 tablets).
    </ParamField>
    <ParamField body="unit" type="String">
      The unit of measure for `quantity` (e.g., `"tablet"`, `"mL"`, `"g"`).
    </ParamField>
    <ParamField body="daysSupply" type="Int">
      Number of days the dispensed quantity is expected to last. Used by pharmacies for refill scheduling and benefit adjudication.
    </ParamField>
    <ParamField body="refillsAllowed" type="Int">
      Number of refills authorized beyond the initial fill. A value of `0` means no refills.
    </ParamField>
    <ParamField body="dispenseAsWritten" type="Boolean">
      When `true`, instructs the pharmacy not to substitute a generic equivalent. Defaults to `false`.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="clinical" type="PrescriptionClinicalInput">
  Clinical context specific to this prescription. Note that patient-level diagnoses are managed separately through the [patient mutation](/api/patient).

  <Expandable title="PrescriptionClinicalInput fields">
    <ParamField body="diagnoses" type="DiagnosesPatch">
      Indication diagnoses for this specific prescription. Uses add/remove patch semantics — send only the delta.

      <Expandable title="DiagnosesPatch fields">
        <ParamField body="add" type="[DiagnosisReferenceInput!]">
          Diagnoses to attach. Each entry accepts `id`, `name`, and/or `icd10Code`.
        </ParamField>
        <ParamField body="remove" type="[DiagnosisReferenceInput!]">
          Diagnoses to remove by Photon `id`.
        </ParamField>
        <ParamField body="none" type="Boolean">
          When `true`, clears all diagnoses from this prescription.
        </ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="notes" type="String">
      Prescriber notes visible to the pharmacist. Replaces any existing notes on update.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="signing" type="PrescriptionSigningDetailsInput">
  Cryptographic signing payload. Send this input only after all clinical and treatment edits are finalized. See the note at the top of this page.

  <Expandable title="PrescriptionSigningDetailsInput fields">
    <ParamField body="signedHash" type="String">
      The `contentHash` value from the most recent response, sent back unchanged. Signing requires prescriber permission; otherwise the call returns `UnauthorizedError` with code `PRESCRIPTION_SIGNING_UNAUTHORIZED`.
    </ParamField>
    <ParamField body="message" type="String">
      An optional human-readable attestation message (e.g., `"Signed by Dr. Ada Lovelace, MD"`). Stored alongside the signature for audit purposes.
    </ParamField>
  </Expandable>
</ParamField>

## Returns

The mutation returns a `PrescriptionResult` union. Handle all four variants in your client.

<ResponseField name="PrescriptionPayload" type="union variant">
  Returned when the operation succeeds.

  <Expandable title="PrescriptionPayload fields">
    <ResponseField name="prescription" type="Prescription">
      The full prescription record after changes are applied.

      <Expandable title="Key Prescription fields">
        <ResponseField name="id" type="ID!">Photon prescription ID.</ResponseField>
        <ResponseField name="status" type="DraftStatus">
          Readiness indicator for signing. `READY` means the prescription can be signed. `WARNING` means screening alerts exist but signing is permitted. `BLOCKED` means one or more critical alerts must be resolved before signing.
        </ResponseField>
        <ResponseField name="screeningAlerts" type="[ScreeningAlert!]">
          Clinical decision support alerts generated by the screening engine. Each alert carries a `severity`, `type`, and `description`. Always inspect this list before presenting a signing UI.
        </ResponseField>
        <ResponseField name="signing" type="PrescriptionSigningDetails!">
          <Expandable title="PrescriptionSigningDetails fields">
            <ResponseField name="state" type="PrescriptionSigningState!">
              One of `UNSIGNED`, `SIGNED`, or `INVALIDATED_SIGN`. A prescription moves to `INVALIDATED_SIGN` if clinical data is edited after signing, requiring a new signature.
            </ResponseField>
            <ResponseField name="contentHash" type="String!">
              A deterministic hash of the prescription's current signable content. This value is freshly computed and returned on every response — it changes whenever any signable field is updated. Use the value from your most recent response as the input to your signing operation when preparing the `signedHash`. Never cache a `contentHash` across mutation calls.
            </ResponseField>
            <ResponseField name="message" type="String">
              The attestation message provided at signing time.
            </ResponseField>
            <ResponseField name="signedAt" type="Date">
              Timestamp of the most recent successful signing.
            </ResponseField>
          </Expandable>
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="appliedChanges" type="[Change!]!">
      Field-level changes that were persisted. Each `Change` includes `key`, `status`, `severity`, `reason`, and a `detail` with the before/after values.
    </ResponseField>
    <ResponseField name="unappliedChanges" type="[Change!]!">
      Changes that were requested but not applied. Inspect this list to detect silent no-ops.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="AmbiguousPrescriptionMatch" type="union variant">
  Returned when Photon cannot uniquely identify the prescription to update. No record is created or modified.

  <Expandable title="AmbiguousPrescriptionMatch fields">
    <ResponseField name="candidates" type="[PrescriptionCandidate!]!">
      Matching prescription drafts. Each `PrescriptionCandidate` exposes `id`, `instructions`, and `dispense`.
    </ResponseField>
    <ResponseField name="reason" type="String!">
      Human-readable explanation of the ambiguous match.
    </ResponseField>
  </Expandable>

  To resolve, retry the mutation with `prescription.id` set to the `id` of the intended candidate.
</ResponseField>

<ResponseField name="UnauthorizedError" type="union variant">
  Returned when the caller's token lacks the required permission.

  <Expandable title="UnauthorizedError fields">
    <ResponseField name="code" type="String!">Machine-readable error code.</ResponseField>
    <ResponseField name="message" type="String!">Human-readable description.</ResponseField>
    <ResponseField name="requiredPermission" type="String">The permission scope needed to complete this call.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="UpstreamServiceError" type="union variant">
  Returned when a downstream service (e.g., the screening engine) fails.

  <Expandable title="UpstreamServiceError fields">
    <ResponseField name="code" type="String!">Machine-readable error code.</ResponseField>
    <ResponseField name="message" type="String!">Human-readable description.</ResponseField>
    <ResponseField name="service" type="String!">Name of the failing upstream service.</ResponseField>
    <ResponseField name="retryable" type="Boolean!">When `true`, a retry after a short delay is safe.</ResponseField>
  </Expandable>
</ResponseField>
