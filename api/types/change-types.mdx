The change model is central to how the Photon Rx API communicates what it did — and what it couldn't do automatically — in response to a mutation. Every payload type (`PatientPayload`, `PrescriptionPayload`, `OrderPayload`) implements the `ChangeSet` interface, which carries two arrays: changes the API applied on your behalf and changes it could not resolve without additional input from you. Each individual `Change` describes the field or entity affected, the operation performed, and the resolution options available if disambiguation is needed.

---

## ChangeSet

A shared interface implemented by all mutation payload types. It surfaces the results of the API's automated reasoning about how to fulfill your request.

```graphql
interface ChangeSet {
  appliedChanges: [Change!]!
  unappliedChanges: [Change!]!
}
```

<ResponseField name="appliedChanges" type="[Change!]!" required>
  The list of changes the API successfully applied to the record. Each entry describes a field modification, entity resolution, or pharmacy selection that was completed without requiring additional input.
</ResponseField>

<ResponseField name="unappliedChanges" type="[Change!]!" required>
  The list of changes the API could not automatically apply. Each entry describes a field or entity that requires you to supply additional input — for example, selecting among multiple matching drug records or resolving an ambiguous pharmacy.
</ResponseField>

## Change

A structured description of a single modification or resolution attempt on a field or entity within a record.

```graphql
type Change {
  key: String!
  label: String!
  status: ChangeStatus!
  severity: ChangeSeverity!
  reason: String
  options: [ChangeOption!]
  category: ChangeCategory
  operation: ChangeOperation!
  detail: ChangeDetail!
}
```

<ResponseField name="key" type="String!" required>
  A machine-readable identifier for the change within this response (e.g., `"demographic.phone"` or `"clinical.allergies.add.0"`). To resolve a change, set the option's `value` at its `argument` path — not at `key`.
</ResponseField>

<ResponseField name="label" type="String!" required>
  A human-readable label describing what field or entity this change applies to (e.g., `"Postal Code"` or `"Treatment"`).
</ResponseField>

<ResponseField name="status" type="ChangeStatus!" required>
  Whether the change was applied, rejected, or is waiting for disambiguation. One of `APPLIED`, `REJECTED`, or `AMBIGUOUS`.
</ResponseField>

<ResponseField name="severity" type="ChangeSeverity!" required>
  How urgently this change requires attention. One of `INFO`, `ADVISORY`, or `BLOCKING`. A `BLOCKING` change must be resolved before the record can proceed to the next workflow step.
</ResponseField>

<ResponseField name="reason" type="String">
  A human-readable explanation of why the API applied, rejected, or flagged this change (e.g., `"The provided RxNorm code matched a more specific product"` or `"Multiple matching pharmacies found within range"`).
</ResponseField>

<ResponseField name="options" type="[ChangeOption!]">
  When `status` is `AMBIGUOUS`, this field contains the resolution options available for you to choose from. Submit your selection back to the API using the option's `operation` and `argument` values.
</ResponseField>

<ResponseField name="category" type="ChangeCategory">
  The functional category of this change. See [ChangeCategory](#changecategory) for the full list of values.
</ResponseField>

<ResponseField name="operation" type="ChangeOperation!" required>
  The type of modification this change represents. One of `ADDED`, `MODIFIED`, or `REMOVED`.
</ResponseField>

<ResponseField name="detail" type="ChangeDetail!" required>
  Structured detail about what changed, expressed as one of three concrete types. Use `__typename` to determine which type you are working with. See [ChangeDetail](#changedetail) below.
</ResponseField>

## ChangeDetail

A union type that carries structured context about the change, depending on whether it is a scalar field modification, an entity resolution, or a pharmacy resolution.

```graphql
union ChangeDetail = FieldChangeDetail | EntityResolutionDetail | PharmacyResolutionDetail
```

### FieldChangeDetail

Describes a change to a scalar field, providing the value before and after the change.

<ResponseField name="previousValue" type="TypedValue">
  The field's value before the change was applied. `null` when the field did not previously have a value (i.e., an `ADDED` operation).

  <Expandable title="TypedValue variants">
    `TypedValue` is an interface with two concrete implementations:

    **TextValue**
    <ResponseField name="displayValue" type="String!" required>
      A formatted string suitable for display in a UI.
    </ResponseField>
    <ResponseField name="value" type="String!" required>
      The raw string value.
    </ResponseField>

    **QuantityValue**
    <ResponseField name="displayValue" type="String!" required>
      A formatted string combining the numeric value and unit (e.g., `"30 tablets"`).
    </ResponseField>
    <ResponseField name="value" type="Float!" required>
      The raw numeric quantity.
    </ResponseField>
    <ResponseField name="unit" type="String!" required>
      The unit of measure for the quantity (e.g., `"tablets"`, `"mL"`).
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="newValue" type="TypedValue">
  The field's value after the change was applied. `null` when the field's value was removed (i.e., a `REMOVED` operation).
</ResponseField>

### EntityResolutionDetail

Describes how the API resolved a free-text or coded entity reference (such as a drug name or diagnosis code) to a specific record in its catalog.

<ResponseField name="inputText" type="String">
  The original text or code that was provided as input (e.g., `"lisinopril 10mg"` or `"E11"`).
</ResponseField>

<ResponseField name="resolvedEntityId" type="ID">
  The identifier of the catalog entity the API resolved the input to. `null` when resolution failed or is pending disambiguation.
</ResponseField>

### PharmacyResolutionDetail

Describes how the API resolved a pharmacy selection, including pricing offers for each candidate. See [PharmacyResolutionDetail](/api/types/pharmacy-types#pharmacyresolutiondetail) in the Pharmacy Types reference.

## ChangeOption

An interface representing a selectable resolution option for an `AMBIGUOUS` change. Submit the `operation` and `argument` from your chosen option to resolve the change.

```graphql
interface ChangeOption {
  displayName: String!
  reason: String
  operation: String!
  argument: String
  value: String
  match: EntityMatch
}
```

<ResponseField name="displayName" type="String!" required>
  A human-readable label for this option, suitable for display in a disambiguation UI (e.g., `"Lisinopril 10 mg oral tablet (RxCUI: 314076)"`).
</ResponseField>

<ResponseField name="reason" type="String">
  An explanation of why this option is being offered (e.g., `"Exact name match in the drug catalog"`).
</ResponseField>

<ResponseField name="operation" type="String!" required>
  The operation identifier to submit when selecting this option. Pass this value back to the relevant mutation argument.
</ResponseField>

<ResponseField name="argument" type="String">
  An optional argument to accompany the operation when selecting this option.
</ResponseField>

<ResponseField name="value" type="String">
  The raw value associated with this option, such as an entity ID or coded value.
</ResponseField>

<ResponseField name="match" type="EntityMatch">
  Metadata describing how confidently this option matches the original input.

  <Expandable title="EntityMatch fields">
    <ResponseField name="matchType" type="EntityMatchType!" required>
      The method by which this option was matched to the input. One of `EXACT_NAME_MATCH`, `FUZZY_NAME_MATCH`, `RXNORM_CODE_MATCH`, or `DRUG_CLASS_MATCH`.
    </ResponseField>
    <ResponseField name="confidence" type="ConfidenceLevel">
      The API's confidence in this match. One of `LOW`, `MEDIUM`, or `HIGH`.
    </ResponseField>
  </Expandable>
</ResponseField>

### GenericChangeOption

The default concrete implementation of the `ChangeOption` interface. It carries all fields defined by the interface without additional properties. See [PharmacyChangeOption](/api/types/pharmacy-types#pharmacychangeoption) for a pharmacy-specific variant that extends this interface with pricing offers.

## Example: Full Change Object

The following example shows a `Change` with `AMBIGUOUS` status, representing a treatment field that matched two drug catalog entries and requires disambiguation.

```json
{
  "key": "prescription.treatment",
  "label": "Treatment",
  "status": "AMBIGUOUS",
  "severity": "BLOCKING",
  "reason": "Multiple drug catalog entries matched the provided treatment name.",
  "operation": "MODIFIED",
  "category": "DISAMBIGUATION",
  "detail": {
    "__typename": "EntityResolutionDetail",
    "inputText": "lisinopril 10mg",
    "resolvedEntityId": null
  },
  "options": [
    {
      "__typename": "GenericChangeOption",
      "displayName": "Lisinopril 10 mg oral tablet",
      "reason": "Exact name match",
      "operation": "SET_TREATMENT",
      "argument": "treatment_id",
      "value": "rxnorm_314076",
      "match": {
        "matchType": "EXACT_NAME_MATCH",
        "confidence": "HIGH"
      }
    },
    {
      "__typename": "GenericChangeOption",
      "displayName": "Lisinopril 10 mg / Hydrochlorothiazide 12.5 mg oral tablet",
      "reason": "Partial name match",
      "operation": "SET_TREATMENT",
      "argument": "treatment_id",
      "value": "rxnorm_203160",
      "match": {
        "matchType": "FUZZY_NAME_MATCH",
        "confidence": "MEDIUM"
      }
    }
  ]
}
```

## Enums

### ChangeStatus

Indicates whether the API was able to apply a change automatically.

| Value       | Description                                                                                                          |
|-------------|----------------------------------------------------------------------------------------------------------------------|
| `APPLIED`   | The change was applied to the record without requiring additional input.                                             |
| `REJECTED`  | The change could not be applied and was discarded. The `reason` field explains why.                                  |
| `AMBIGUOUS` | The change could not be automatically resolved. Review the `options` field and submit a selection to resolve it.     |

### ChangeSeverity

How urgently a change demands attention.

| Value      | Description                                                                                          |
|------------|------------------------------------------------------------------------------------------------------|
| `INFO`     | Informational only; no action is required.                                                           |
| `ADVISORY` | You should review this change, but it does not block the record from proceeding.                     |
| `BLOCKING` | This change must be resolved before the record can advance to the next workflow step (e.g., signing).|

### ChangeOperation

The type of modification a change represents.

| Value      | Description                                           |
|------------|-------------------------------------------------------|
| `ADDED`    | A new value was added to a previously empty field.    |
| `MODIFIED` | An existing field value was replaced with a new one.  |
| `REMOVED`  | An existing field value was cleared.                  |

### ChangeCategory

The functional reason behind a change.

| Value                   | Description                                                                                        |
|-------------------------|----------------------------------------------------------------------------------------------------|
| `DISAMBIGUATION`        | The API requires you to choose among multiple matching candidates.                                 |
| `OBSOLETE_REFERENCE`    | The referenced entity (e.g., an NDC) is no longer active and was updated to a current equivalent. |
| `CODING_SPECIFICITY`    | The input code was valid but too broad; the API resolved it to a more specific code.               |
| `COST_SAVINGS`          | A therapeutically equivalent alternative with lower cost was identified.                           |
| `PRODUCT_PREFERENCE`    | The change reflects a formulary or network preference.                                             |
| `SAFETY`                | The change was triggered by a clinical safety concern.                                             |
| `MISSING_INPUT`         | Required information was absent from the input.                                                    |
| `INVALID_INPUT`         | The provided input did not pass validation.                                                        |
| `CONFIRMATION_REQUIRED` | The action requires explicit confirmation before it can be completed.                              |

### ConfidenceLevel

The API's confidence in an entity match.

| Value    | Description                                               |
|----------|-----------------------------------------------------------|
| `LOW`    | The match is tentative and should be reviewed carefully.  |
| `MEDIUM` | The match is likely correct but not definitive.           |
| `HIGH`   | The match is highly confident and likely exact.           |

### EntityMatchType

Describes the method used to match an input value to a catalog entity.

| Value               | Description                                                                  |
|---------------------|------------------------------------------------------------------------------|
| `EXACT_NAME_MATCH`  | The input text matched a catalog entry's name exactly.                       |
| `FUZZY_NAME_MATCH`  | The input text matched a catalog entry's name approximately.                 |
| `RXNORM_CODE_MATCH` | The input RxNorm code (RxCUI) matched a catalog entry directly.              |
| `DRUG_CLASS_MATCH`  | The input was matched at the drug class level rather than the product level. |
