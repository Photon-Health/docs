Prescription types represent the full lifecycle of a medication order — from a draft prescription awaiting signature to a signed and submitted record. Each prescription carries details about the treatment being dispensed, clinical context like diagnoses, drug-screening alerts that may block or warn on signing, and cryptographic signing metadata used to verify the prescriber's intent.

---

## Prescription

The root prescription object returned by prescription queries and mutations.

```graphql
type Prescription {
  id: ID!
  status: DraftStatus
  screeningAlerts: [ScreeningAlert!]
  patient: PatientReference
  templateId: ID
  treatment: Treatment!
  instructions: String
  dispense: Dispense
  clinical: PrescriptionClinical
  signing: PrescriptionSigningDetails!
}
```

<ResponseField name="id" type="ID!" required>
  The unique identifier for the prescription.
</ResponseField>

<ResponseField name="status" type="DraftStatus">
  The readiness status of the draft prescription. One of `READY`, `WARNING`, or `BLOCKED`. A prescription with a `BLOCKED` status cannot be signed until the blocking condition is resolved.
</ResponseField>

<ResponseField name="screeningAlerts" type="[ScreeningAlert!]">
  A list of clinical screening alerts generated for this prescription. Alerts may flag drug–drug interactions, allergen conflicts, or contraindicated conditions. Returns `null` when no screening has been performed.

  <Expandable title="ScreeningAlert fields">
    <ResponseField name="severity" type="ScreeningSeverity!" required>
      The clinical significance of the alert. One of `MINOR`, `MODERATE`, or `MAJOR`.
    </ResponseField>
    <ResponseField name="type" type="ScreeningAlertType!" required>
      The category of clinical risk. One of `DRUG` (drug–drug interaction), `ALLERGEN` (allergen conflict), or `CONDITION` (contraindicated diagnosis).
    </ResponseField>
    <ResponseField name="description" type="String!" required>
      A human-readable description of the clinical risk (e.g., `"Potential interaction between warfarin and ibuprofen"`).
    </ResponseField>
    <ResponseField name="involvedEntities" type="[InvolvedEntity!]!" required>
      The drugs, allergens, or conditions involved in the alert.

      <Expandable title="InvolvedEntity fields">
        <ResponseField name="id" type="ID!" required>
          The unique identifier of the involved entity.
        </ResponseField>
        <ResponseField name="name" type="String!" required>
          The human-readable name of the involved entity (e.g., `"Warfarin"` or `"Penicillin allergy"`).
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="category" type="ChangeCategory!" required>
      The change category associated with this alert. See [ChangeCategory](/api/types/change-types#changecategory) for the full list of values.
    </ResponseField>
    <ResponseField name="options" type="[ChangeOption!]">
      Resolution options you can submit to acknowledge or override the alert. See [ChangeOption](/api/types/change-types#changeoption) for the field reference.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="patient" type="PatientReference">
  A reference to the patient for whom the prescription is written, including a snapshot of their demographic data at the time of prescribing.

  <Expandable title="PatientReference fields">
    <ResponseField name="id" type="ID!" required>
      The unique identifier of the referenced patient.
    </ResponseField>
    <ResponseField name="demographic" type="PatientDemographic">
      A snapshot of the patient's demographic data. See [PatientDemographic](/api/types/patient-types#patientdemographic) for the full field reference.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="templateId" type="ID">
  The identifier of the prescription template used to pre-populate this prescription, if applicable.
</ResponseField>

<ResponseField name="treatment" type="Treatment!" required>
  The drug or treatment being prescribed.

  <Expandable title="Treatment fields">
    <ResponseField name="id" type="ID!" required>
      The unique identifier for this treatment record.
    </ResponseField>
    <ResponseField name="name" type="String!" required>
      The human-readable name of the treatment (e.g., `"Lisinopril 10 mg oral tablet"`).
    </ResponseField>
    <ResponseField name="rxNormId" type="String">
      The RxNorm concept unique identifier (RxCUI) for this treatment.
    </ResponseField>
    <ResponseField name="ndc" type="String">
      The National Drug Code (NDC) for the specific drug package, when known.
    </ResponseField>
    <ResponseField name="upc" type="String">
      The Universal Product Code (UPC) for this treatment, when applicable.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="instructions" type="String">
  The sig (signa) — patient-facing directions for taking the medication (e.g., `"Take 1 tablet by mouth once daily"`).
</ResponseField>

<ResponseField name="dispense" type="Dispense">
  Quantity and supply details controlling what is dispensed at the pharmacy.

  <Expandable title="Dispense fields">
    <ResponseField name="quantity" type="Float">
      The numeric quantity to dispense (e.g., `30.0`).
    </ResponseField>
    <ResponseField name="unit" type="String">
      The unit of measure for the dispensed quantity (e.g., `"tablets"`, `"mL"`).
    </ResponseField>
    <ResponseField name="daysSupply" type="Int">
      The number of days the dispensed quantity is expected to last.
    </ResponseField>
    <ResponseField name="refillsAllowed" type="Int">
      The number of authorized refills remaining on this prescription.
    </ResponseField>
    <ResponseField name="dispenseAsWritten" type="Boolean">
      When `true`, the pharmacist must dispense the exact product specified and may not substitute a generic equivalent.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="clinical" type="PrescriptionClinical">
  Clinical context attached to the prescription, including associated diagnoses and free-text notes.

  <Expandable title="PrescriptionClinical fields">
    <ResponseField name="diagnoses" type="[Diagnosis!]!" required>
      Diagnoses associated with this prescription. See [Diagnosis](/api/types/patient-types#diagnosis) for the field reference.
    </ResponseField>
    <ResponseField name="notes" type="String">
      Free-text clinical notes relevant to this prescription.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="signing" type="PrescriptionSigningDetails!" required>
  Metadata about the signing state of the prescription, including cryptographic verification details.

  <Expandable title="PrescriptionSigningDetails fields">
    <ResponseField name="state" type="PrescriptionSigningState!" required>
      The current signing state. One of `UNSIGNED`, `SIGNED`, or `INVALIDATED_SIGN`. A prescription in the `INVALIDATED_SIGN` state was signed but subsequently modified, requiring it to be re-signed.
    </ResponseField>
    <ResponseField name="contentHash" type="String!" required>
      A hash of the prescription's current clinically significant fields (excludes notes), recomputed on every response. Send it back as `signing.signedHash` to sign.
    </ResponseField>
    <ResponseField name="message" type="String">
      A human-readable message about the signing state (e.g., a reason why a signature was invalidated).
    </ResponseField>
    <ResponseField name="signedAt" type="Date">
      The date and time the prescription was signed, in ISO 8601 format.
    </ResponseField>
  </Expandable>
</ResponseField>

## PrescriptionPayload

Returned by prescription mutations. Wraps the resulting prescription together with structured information about what the API changed and what it could not automatically resolve.

`PrescriptionPayload` implements the [`ChangeSet`](/api/types/change-types#changeset) interface.

```graphql
type PrescriptionPayload implements ChangeSet {
  prescription: Prescription
  appliedChanges: [Change!]!
  unappliedChanges: [Change!]!
}
```

<ResponseField name="prescription" type="Prescription">
  The resulting prescription record after the mutation was applied.
</ResponseField>

<ResponseField name="appliedChanges" type="[Change!]!" required>
  Changes the API successfully applied to the prescription record. See [Change Types](/api/types/change-types) for the full field reference.
</ResponseField>

<ResponseField name="unappliedChanges" type="[Change!]!" required>
  Changes the API could not automatically apply — for example, treatments with ambiguous matches that require you to select a resolution. See [Change Types](/api/types/change-types) for the full field reference.
</ResponseField>

## AmbiguousPrescriptionMatch

Returned when a prescription lookup matches more than one candidate record. You must resolve the ambiguity by selecting one of the candidates before proceeding.

```graphql
type AmbiguousPrescriptionMatch {
  candidates: [PrescriptionCandidate!]!
  reason: String!
}
```

<ResponseField name="candidates" type="[PrescriptionCandidate!]!" required>
  The list of prescriptions that matched the lookup criteria.

  <Expandable title="PrescriptionCandidate fields">
    <ResponseField name="id" type="ID!" required>
      The unique identifier of the candidate prescription.
    </ResponseField>
    <ResponseField name="instructions" type="String">
      The sig (patient directions) from the candidate prescription, to help you distinguish between candidates.
    </ResponseField>
    <ResponseField name="dispense" type="Dispense">
      The dispense details from the candidate prescription. See [Dispense](#dispense) for the field reference.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="reason" type="String!" required>
  A human-readable explanation of why the match was ambiguous.
</ResponseField>

## Enums

### DraftStatus

Indicates whether a draft prescription is ready to be signed.

| Value     | Description                                                                                      |
|-----------|--------------------------------------------------------------------------------------------------|
| `READY`   | The prescription has no issues and is ready for the prescriber to sign.                          |
| `WARNING` | The prescription has one or more non-blocking screening alerts. You may still sign it.           |
| `BLOCKED` | The prescription has one or more blocking issues that must be resolved before it can be signed.  |

### PrescriptionSigningState

Tracks the signing lifecycle of a prescription.

| Value               | Description                                                                                          |
|---------------------|------------------------------------------------------------------------------------------------------|
| `UNSIGNED`          | The prescription has not yet been signed by the prescriber.                                          |
| `SIGNED`            | The prescription has been signed and the content hash is valid.                                      |
| `INVALIDATED_SIGN`  | The prescription was signed but has since been modified, invalidating the original signature.        |

### ScreeningSeverity

The clinical significance level of a screening alert.

| Value      | Description                                                           |
|------------|-----------------------------------------------------------------------|
| `MINOR`    | Low clinical significance; generally informational.                   |
| `MODERATE` | Moderate clinical significance; review is recommended.                |
| `MAJOR`    | High clinical significance; may block signing or require override.    |

### ScreeningAlertType

The category of clinical risk flagged by a screening alert.

| Value      | Description                                                              |
|------------|--------------------------------------------------------------------------|
| `DRUG`     | A drug–drug or drug–food interaction has been detected.                  |
| `ALLERGEN` | The prescribed treatment conflicts with a known patient allergy.         |
| `CONDITION`| The prescribed treatment is contraindicated given a patient diagnosis.   |
