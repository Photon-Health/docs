The patient types model everything the Photon Rx API knows about an individual — from demographic details like name, date of birth, and insurance benefits to clinical information such as allergies, active medications, and diagnoses. Payload types wrap mutation results and carry structured change information alongside the patient record itself.

---

## Patient

The root patient object returned by patient queries and mutations.

```graphql
type Patient {
  id: ID!
  demographic: PatientDemographic
  clinical: PatientClinical
}
```

<ResponseField name="id" type="ID!" required>
  The unique identifier for the patient record.
</ResponseField>

<ResponseField name="demographic" type="PatientDemographic">
  Demographic information for the patient, including name, contact details, address, insurance benefits, and preferred pharmacy.

  <Expandable title="PatientDemographic fields">
    <ResponseField name="name" type="HumanName!" required>
      The patient's full name, broken into individual components.

      <Expandable title="HumanName fields">
        <ResponseField name="title" type="String">
          An honorific or title prefix (e.g., `"Dr."`, `"Ms."`).
        </ResponseField>
        <ResponseField name="first" type="String">
          The patient's first (given) name.
        </ResponseField>
        <ResponseField name="middle" type="String">
          The patient's middle name or initial.
        </ResponseField>
        <ResponseField name="last" type="String">
          The patient's last (family) name.
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="dateOfBirth" type="Date">
      The patient's date of birth in `YYYY-MM-DD` format.
    </ResponseField>

    <ResponseField name="sex" type="Sex">
      The patient's biological sex. One of `MALE`, `FEMALE`, or `UNKNOWN`.
    </ResponseField>

    <ResponseField name="gender" type="String">
      The patient's self-identified gender as a free-form string.
    </ResponseField>

    <ResponseField name="email" type="String">
      The patient's email address.
    </ResponseField>

    <ResponseField name="phone" type="String">
      The patient's phone number.
    </ResponseField>

    <ResponseField name="address" type="PatientAddress">
      The patient's mailing or home address.

      <Expandable title="PatientAddress fields">
        <ResponseField name="street1" type="String">
          Primary street address line.
        </ResponseField>
        <ResponseField name="street2" type="String">
          Secondary address line (apartment, suite, unit, etc.).
        </ResponseField>
        <ResponseField name="city" type="String">
          City name.
        </ResponseField>
        <ResponseField name="state" type="String">
          State or province code (e.g., `"CA"`, `"TX"`).
        </ResponseField>
        <ResponseField name="postalCode" type="String">
          ZIP or postal code.
        </ResponseField>
        <ResponseField name="country" type="String">
          ISO 3166-1 alpha-2 country code (e.g., `"US"`).
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="benefits" type="[Benefit!]!" required>
      A list of pharmacy benefit (insurance) records associated with the patient. Returns an empty array when no benefits are on file.

      <Expandable title="Benefit fields">
        <ResponseField name="id" type="ID!" required>
          Unique identifier for this benefit record.
        </ResponseField>
        <ResponseField name="bin" type="String!" required>
          The Bank Identification Number used for pharmacy claims routing.
        </ResponseField>
        <ResponseField name="pcn" type="String">
          The Processor Control Number, which further identifies the PBM processor.
        </ResponseField>
        <ResponseField name="groupId" type="String">
          The insurance group identifier.
        </ResponseField>
        <ResponseField name="memberId" type="String!" required>
          The member's unique identifier on their insurance plan.
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="preferredPharmacy" type="Pharmacy">
      The patient's preferred pharmacy, if one has been set. See [Pharmacy Types](/api/types/pharmacy-types) for the full field reference.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="clinical" type="PatientClinical">
  Clinical information for the patient, including allergies, medication history, diagnoses, and free-text notes.

  <Expandable title="PatientClinical fields">
    <ResponseField name="allergies" type="[Allergy!]!" required>
      The patient's known drug and substance allergies. Returns an empty array when none are recorded.

      <Expandable title="Allergy fields">
        <ResponseField name="id" type="ID!" required>
          Unique identifier for the allergy record.
        </ResponseField>
        <ResponseField name="name" type="String!" required>
          Human-readable name of the allergen (e.g., `"Penicillin"`).
        </ResponseField>
        <ResponseField name="rxNormId" type="String">
          The RxNorm concept unique identifier (RxCUI) for the allergen, when available.
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="medications" type="[MedicationHistoryEntry!]!" required>
      The patient's medication history, including both active and historical entries. Returns an empty array when no history is recorded.

      <Expandable title="MedicationHistoryEntry fields">
        <ResponseField name="id" type="ID!" required>
          Unique identifier for this medication history entry.
        </ResponseField>
        <ResponseField name="name" type="String!" required>
          Human-readable name of the medication (e.g., `"Metformin 500 mg oral tablet"`).
        </ResponseField>
        <ResponseField name="rxNormId" type="String">
          The RxNorm concept unique identifier (RxCUI) for the medication, when available.
        </ResponseField>
        <ResponseField name="status" type="MedicationHistoryStatus!" required>
          The current status of this medication. One of `ACTIVE`, `HISTORICAL`, or `UNKNOWN`.
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="diagnoses" type="[Diagnosis!]!" required>
      The patient's recorded diagnoses. Returns an empty array when none are on file.

      <Expandable title="Diagnosis fields">
        <ResponseField name="id" type="ID!" required>
          Unique identifier for the diagnosis record.
        </ResponseField>
        <ResponseField name="name" type="String">
          Human-readable diagnosis name (e.g., `"Type 2 diabetes mellitus"`).
        </ResponseField>
        <ResponseField name="icd10Code" type="String">
          The ICD-10-CM code for this diagnosis (e.g., `"E11.9"`).
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="notes" type="String">
      Free-text clinical notes associated with the patient.
    </ResponseField>
  </Expandable>
</ResponseField>

## PatientPayload

Returned by patient mutations. Wraps the resulting patient record together with structured information about what the API changed and what it could not automatically resolve.

`PatientPayload` implements the [`ChangeSet`](/api/types/change-types#changeset) interface.

```graphql
type PatientPayload implements ChangeSet {
  patient: PatientRecordResult
  appliedChanges: [Change!]!
  unappliedChanges: [Change!]!
}
```

<ResponseField name="patient" type="PatientRecordResult">
  The resulting patient record, or an upstream service error if the record could not be retrieved. This field is a union of `Patient` and `UpstreamServiceError` — use the `__typename` field to distinguish between them.
</ResponseField>

<ResponseField name="appliedChanges" type="[Change!]!" required>
  Changes the API successfully applied to the patient record. See [Change Types](/api/types/change-types) for the full field reference.
</ResponseField>

<ResponseField name="unappliedChanges" type="[Change!]!" required>
  Changes the API could not automatically apply — for example, fields with ambiguous matches that require you to select a resolution. See [Change Types](/api/types/change-types) for the full field reference.
</ResponseField>

## AmbiguousPatientMatch

Returned when a patient lookup matches more than one candidate record. You must resolve the ambiguity by selecting one of the candidates before proceeding.

```graphql
type AmbiguousPatientMatch {
  candidates: [PatientCandidate!]!
  reason: String!
}
```

<ResponseField name="candidates" type="[PatientCandidate!]!" required>
  The list of patient records that matched the lookup criteria.

  <Expandable title="PatientCandidate fields">
    <ResponseField name="id" type="ID!" required>
      The unique identifier of the candidate patient record.
    </ResponseField>
    <ResponseField name="firstName" type="String!" required>
      The candidate's first name.
    </ResponseField>
    <ResponseField name="lastName" type="String">
      The candidate's last name.
    </ResponseField>
    <ResponseField name="dateOfBirth" type="Date">
      The candidate's date of birth in `YYYY-MM-DD` format.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="reason" type="String!" required>
  A human-readable explanation of why the match was ambiguous (e.g., `"Multiple patients share the same name and date of birth"`).
</ResponseField>

## Enums

### Sex

Represents the patient's biological sex as recorded in their medical record.

| Value     | Description                                      |
|-----------|--------------------------------------------------|
| `MALE`    | The patient's biological sex is male.            |
| `FEMALE`  | The patient's biological sex is female.          |
| `UNKNOWN` | The patient's biological sex is not on record.   |

### MedicationHistoryStatus

Indicates whether a medication history entry represents a current or past medication.

| Value        | Description                                                          |
|--------------|----------------------------------------------------------------------|
| `ACTIVE`     | The patient is currently taking this medication.                     |
| `HISTORICAL` | The patient has previously taken this medication but no longer does. |
| `UNKNOWN`    | The currency of this medication entry is not known.                  |
