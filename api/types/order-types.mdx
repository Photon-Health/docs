---
title: "Order Output Types"
description: "Reference for all order-related output types in the Photon Rx GraphQL API, including order payloads, ambiguous match resolution, and order state values."
---

Order types represent the routing of one or more prescriptions to a pharmacy for fulfillment. An order groups prescriptions together and tracks their collective state from initial draft through submission or cancellation. Payload types wrap mutation results with structured change data, and ambiguous match types surface when an order lookup returns multiple candidates that require your resolution.

---

## Order

The root order object returned by order queries and mutations.

```graphql
type Order {
  id: ID!
  state: OrderState!
  patient: PatientRecordResult
  prescriptions: [Prescription!]!
  pharmacy: Pharmacy
  exceptions: [OrderException!]!
}
```

<ResponseField name="id" type="ID!" required>
  The unique identifier for the order.
</ResponseField>

<ResponseField name="state" type="OrderState!" required>
  The order's lifecycle state. Defaults to `DRAFT`.
</ResponseField>

<ResponseField name="patient" type="PatientRecordResult">
  The patient on the order (`Patient` or `UpstreamServiceError`). Null only for a legacy or orphaned order with no patient on file.
</ResponseField>

<ResponseField name="prescriptions" type="[Prescription!]!" required>
  The prescriptions included in this order. See [`Prescription`](/api/types/prescription-types).
</ResponseField>

<ResponseField name="pharmacy" type="Pharmacy">
  The pharmacy this order has been routed to. Null when unassigned — the patient chooses from the marketplace.
</ResponseField>

<ResponseField name="exceptions" type="[OrderException!]!" required>
  Problems with this order that need attention. Empty once resolved, and always empty for a `DRAFT` order. See [OrderException](#orderexception).
</ResponseField>

## OrderPayload

Returned by order mutations. Wraps the resulting order together with structured information about what the API changed and what it could not automatically resolve.

`OrderPayload` implements the [`ChangeSet`](/api/types/change-types#changeset) interface.

```graphql
type OrderPayload implements ChangeSet {
  order: Order
  appliedChanges: [Change!]!
  unappliedChanges: [Change!]!
}
```

<ResponseField name="order" type="Order">
  The resulting order record after the mutation was applied.

  <Expandable title="Order fields">
    <ResponseField name="id" type="ID!" required>
      The unique identifier for the order.
    </ResponseField>
    <ResponseField name="state" type="OrderState!" required>
      The order's lifecycle state.
    </ResponseField>
    <ResponseField name="patient" type="PatientRecordResult">
      The patient on the order.
    </ResponseField>
    <ResponseField name="prescriptions" type="[Prescription!]!" required>
      The prescriptions included in this order.
    </ResponseField>
    <ResponseField name="pharmacy" type="Pharmacy">
      The pharmacy this order has been routed to, or null when unassigned.
    </ResponseField>
    <ResponseField name="exceptions" type="[OrderException!]!" required>
      Problems with this order that need attention.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="appliedChanges" type="[Change!]!" required>
  Changes the API successfully applied to the order record — for example, an automatic pharmacy selection or prescription linkage. See [Change Types](/api/types/change-types) for the full field reference.
</ResponseField>

<ResponseField name="unappliedChanges" type="[Change!]!" required>
  Changes the API could not automatically apply — for example, a pharmacy selection that returned multiple candidates and requires your input. See [Change Types](/api/types/change-types) for the full field reference.
</ResponseField>

## AmbiguousOrderMatch

Returned when an order lookup matches more than one candidate record. You must resolve the ambiguity by selecting one of the candidates before proceeding.

```graphql
type AmbiguousOrderMatch {
  candidates: [OrderCandidate!]!
  reason: String!
}
```

<ResponseField name="candidates" type="[OrderCandidate!]!" required>
  The list of order records that matched the lookup criteria.

  <Expandable title="OrderCandidate fields">
    <ResponseField name="id" type="ID!" required>
      The unique identifier of the candidate order.
    </ResponseField>
    <ResponseField name="pharmacyId" type="ID">
      The identifier of the pharmacy assigned to this candidate order, if one has been set. Useful for distinguishing between candidates destined for different pharmacies.
    </ResponseField>
    <ResponseField name="prescriptionIds" type="[ID!]!" required>
      The list of prescription IDs associated with this candidate order.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="reason" type="String!" required>
  A human-readable explanation of why the match was ambiguous (e.g., `"Multiple open orders contain the same set of prescriptions"`).
</ResponseField>

## OrderException

An open problem with an order, reported for the order as a whole.

```graphql
type OrderException {
  id: ID!
  type: OrderExceptionType!
  message: String
  createdAt: DateTime!
}
```

<ResponseField name="id" type="ID!" required>
  The unique identifier for the exception.
</ResponseField>

<ResponseField name="type" type="OrderExceptionType!" required>
  Why the order needs attention. See [OrderExceptionType](#orderexceptiontype).
</ResponseField>

<ResponseField name="message" type="String">
  A human-readable description of the problem.
</ResponseField>

<ResponseField name="createdAt" type="DateTime!" required>
  When the exception was raised.
</ResponseField>

## Enums

### OrderState

Tracks the lifecycle state of an order from creation through fulfillment or cancellation.

| Value       | Description                                                                                                     |
|-------------|-----------------------------------------------------------------------------------------------------------------|
| `DRAFT` | The order has been created but not yet submitted to a pharmacy. You can still modify a draft order. |
| `SUBMITTED` | The order has been submitted to the pharmacy for fulfillment and is no longer editable.                         |
| `CANCELED` | The order was canceled after submission. Only allowed from `SUBMITTED`. A canceled order cannot be reactivated. |

### OrderExceptionType

Why an order needs attention — usually a problem reaching or using the destination pharmacy.

| Value | Description |
| --- | --- |
| `ORDER_ERROR` | General order error. |
| `DEMOGRAPHIC_MISMATCH` | Patient demographics do not match. |
| `PHARMACY_UNREACHABLE` | The pharmacy cannot be reached. |
| `PHARMACY_CLOSED` | The pharmacy is closed. |
| `EXTERNAL_TRANSFER` | The order was transferred externally. |
| `PHARMACY_DOES_NOT_ACCEPT_INSURANCE` | The pharmacy does not accept the patient's insurance. |
| `PHARMACY_NEEDS_INSURANCE_INFO` | The pharmacy needs insurance information. |
| `SUPERVISING_PHYSICIAN_NEEDED` | A supervising physician is required. |
| `DOCTOR_NOT_LICENSED_IN_STATE` | The prescriber is not licensed in the patient's state. |
