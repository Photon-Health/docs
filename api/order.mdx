---
title: "Order Mutation Breakdown"
description: "Create or update a medication order, attach signed prescriptions, assign a pharmacy, and advance the order through its lifecycle to submission."
---

The `order` mutation is your entry point for managing the full order lifecycle — from creating a draft to submitting it to a pharmacy for fulfillment. An order groups one or more signed prescriptions for a single patient and routes them to a specific pharmacy. You identify a new order by omitting `order.id`; to update an existing one, provide either `order.id` or `order.externalId`. State transitions are controlled through the `state` field, and the mutation returns a detailed change set so you can confirm exactly what was applied.

<Note>
  Orders follow a one-way state machine: `DRAFT` → `SUBMITTED` → `CANCELED`. Once an order moves to `SUBMITTED`, the only permitted mutations are swapping the assigned pharmacy and canceling the order by setting `state` to `CANCELED`. Attempts to edit prescriptions or patient data on a submitted order will be returned in `unappliedChanges`.
</Note>

## Mutation Signature

```graphql
mutation Order($input: OrderInput!, $metadata: RequestMetadata!) {
  order(input: $input, metadata: $metadata) {
    ... on OrderPayload {
      order {
        id
        state
        prescriptions { id }
        pharmacy { id name }
        exceptions { type message }
      }
      appliedChanges { key status severity reason }
      unappliedChanges { key status severity reason }
    }
    ... on AmbiguousOrderMatch {
      candidates { id pharmacyId prescriptionIds }
      reason
    }
    ... on UnauthorizedError {
      code
      message
      requiredPermission
    }
    ... on UpstreamServiceError {
      code
      message
      service
      retryable
    }
  }
}
```

## Arguments

<ParamField body="input" type="OrderInput!" required>
  The order data to create or update. All order fields are nested within this top-level input object.
</ParamField>

<ParamField body="metadata" type="RequestMetadata!" required>
  Request-level metadata used for audit logging and tracing. Required on every call.

  <Expandable title="RequestMetadata fields">
    <ParamField body="source" type="RequestSource!" required>
      The originating surface of this request. One of `WEB_APP`, `EMBEDDABLE_COMPONENT`, `DIRECT_API`, `MCP_CONNECTOR`, or `LLM_AGENT`.
    </ParamField>
    <ParamField body="sourceVersion" type="String">
      Version of the originating client (e.g., `"2.4.1"`).
    </ParamField>
    <ParamField body="client" type="String">
      Human-readable name of the calling application (e.g., `"AcmePractice EHR"`).
    </ParamField>
    <ParamField body="requestId" type="String">
      A caller-supplied ID for tracing this request in your logs. It is not an idempotency key: retrying with the same `requestId` applies the changes again.
    </ParamField>
  </Expandable>
</ParamField>

## OrderInput Fields

<ParamField body="order" type="OrderReferenceInput">
  Reference to an existing order to update. Omit this field entirely to create a new order in `DRAFT` state.

  <Expandable title="OrderReferenceInput fields">
    <ParamField body="id" type="ID">
      The Photon order ID. Use this when you have the Photon-issued identifier.
    </ParamField>
    <ParamField body="externalId" type="String">
      Your system's external identifier for this order. You can use this as an alternative to `id` if you stored your own reference at creation time.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="patient" type="PatientReferenceInput">
  The patient this order belongs to. Reference an existing Photon patient by `id`, or supply demographic data for an inline patient lookup.

  <Expandable title="PatientReferenceInput fields">
    <ParamField body="id" type="ID">
      Photon patient ID. Use this when the patient record already exists.
    </ParamField>
    <ParamField body="demographic" type="PatientDemographicInput">
      Demographic data for an inline patient lookup or creation. See the [patient mutation](/api/patient) for the full field reference.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="prescriptions" type="OrderPrescriptionsPatch">
  The set of signed prescriptions to include in this order. Uses add/remove patch semantics — send only the delta. All referenced prescriptions must be in `SIGNED` state before you can advance the order to `SUBMITTED`.

  <Expandable title="OrderPrescriptionsPatch fields">
    <ParamField body="add" type="[PrescriptionReferenceInput!]">
      Prescriptions to attach to this order. Each entry accepts a Photon `id` or your own `externalId`.

      <Expandable title="PrescriptionReferenceInput fields">
        <ParamField body="id" type="ID">Photon prescription ID.</ParamField>
        <ParamField body="externalId" type="String">Your external reference for the prescription.</ParamField>
      </Expandable>
    </ParamField>

    <ParamField body="remove" type="[PrescriptionReferenceInput!]">
      Prescriptions to detach from this order. Provide the Photon `id` or `externalId` of each prescription to remove. Only permitted while the order is in `DRAFT` state.
    </ParamField>

    <ParamField body="none" type="Boolean">
      When `true`, clears all prescriptions from this order and asserts that no prescriptions should be attached. Useful for resetting a draft before re-populating it.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="state" type="OrderState">
  The target lifecycle state for this order. Omit to leave the state unchanged.

  | Value | Description |
  |-------|-------------|
  | `DRAFT` | Default initial state. The order is editable — you can add or remove prescriptions and update the assigned pharmacy. |
  | `SUBMITTED` | Sends the order to the assigned pharmacy for fulfillment. All prescriptions must be signed. This transition is irreversible except by cancellation. |
  | `CANCELED` | Cancels the order. Only allowed from `SUBMITTED`. A canceled order cannot be reopened. |
</ParamField>

<ParamField body="pharmacy" type="PharmacyReferenceInput">
  The pharmacy to fulfill this order. You can look up a pharmacy by Photon `id`, by `name`, or by proximity search using `near`. Pharmacy assignment can be updated even after an order is submitted.

  <Expandable title="PharmacyReferenceInput fields">
    <ParamField body="id" type="ID">
      Photon pharmacy ID. Use this for a direct, unambiguous assignment.
    </ParamField>
    <ParamField body="name" type="String">
      Pharmacy name. Case-insensitive, partial match (typos are not matched). Combine with `near` to narrow results geographically.
    </ParamField>
    <ParamField body="near" type="LocationInput">
      Location to search around. Only `latLong` with `radiusMiles` filters results; `address` and `latLong` without a radius only sort by distance; `text` is not supported. See [Pharmacy Search](/reference/pharmacy-search).
    </ParamField>
    <ParamField body="openAt" type="Date">
      Filter pharmacies to those open on the specified date (`YYYY-MM-DD`; a date-time value is rejected).
    </ParamField>
    <ParamField body="fulfillmentType" type="FulfillmentType">
      Preferred fulfillment method. One of `MAIL_ORDER` or `PICK_UP`. Filters the pharmacy search to only those that support the requested method.
    </ParamField>
  </Expandable>
</ParamField>

## Returns

The mutation returns an `OrderResult` union. Handle all four variants in your client.

<ResponseField name="OrderPayload" type="union variant">
  Returned when the operation succeeds.

  <Expandable title="OrderPayload fields">
    <ResponseField name="order" type="Order">
      The order record after all changes have been applied.

      <Expandable title="Order fields">
        <ResponseField name="id" type="ID!">
          The Photon-issued order ID. Store this for subsequent updates and status queries.
        </ResponseField>
        <ResponseField name="state" type="OrderState!">
          The order's lifecycle state. Defaults to `DRAFT`.
        </ResponseField>
        <ResponseField name="patient" type="PatientRecordResult">
          The patient on the order (`Patient` or `UpstreamServiceError`). Null only for a legacy or orphaned order with no patient on file.
        </ResponseField>
        <ResponseField name="prescriptions" type="[Prescription!]!">
          The prescriptions currently attached to this order.
        </ResponseField>
        <ResponseField name="pharmacy" type="Pharmacy">
          The pharmacy this order has been routed to. Null when unassigned — the patient chooses from the marketplace.
        </ResponseField>
        <ResponseField name="exceptions" type="[OrderException!]!">
          Problems with this order that need attention, each with `id`, `type` (`OrderExceptionType`), `message`, and `createdAt`. Empty once resolved, and always empty for a `DRAFT` order.
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="appliedChanges" type="[Change!]!">
      Field-level changes that were successfully persisted. Each `Change` includes `key`, `status`, `severity`, `reason`, and a `detail` with the before/after values.
    </ResponseField>

    <ResponseField name="unappliedChanges" type="[Change!]!">
      Changes that were requested but not applied — for example, attempting to add a prescription to a submitted order. Inspect this list to detect silent no-ops and surface issues to the user.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="AmbiguousOrderMatch" type="union variant">
  Returned when Photon cannot uniquely identify the order to update. No record is created or modified.

  <Expandable title="AmbiguousOrderMatch fields">
    <ResponseField name="candidates" type="[OrderCandidate!]!">
      Matching orders. Each `OrderCandidate` exposes `id`, `pharmacyId`, and `prescriptionIds`.
    </ResponseField>
    <ResponseField name="reason" type="String!">
      Human-readable explanation of the ambiguous match.
    </ResponseField>
  </Expandable>

  To resolve, retry the mutation with `input.order.id` set to the `id` of the intended candidate.
</ResponseField>

<ResponseField name="UnauthorizedError" type="union variant">
  Returned when the caller's token lacks the required permission.

  <Expandable title="UnauthorizedError fields">
    <ResponseField name="code" type="String!">Machine-readable error code.</ResponseField>
    <ResponseField name="message" type="String!">Human-readable description of the authorization failure.</ResponseField>
    <ResponseField name="requiredPermission" type="String">The permission scope needed to complete this call.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="UpstreamServiceError" type="union variant">
  Returned when a downstream dependency fails.

  <Expandable title="UpstreamServiceError fields">
    <ResponseField name="code" type="String!">Machine-readable error code.</ResponseField>
    <ResponseField name="message" type="String!">Human-readable description of the failure.</ResponseField>
    <ResponseField name="service" type="String!">Name of the upstream service that failed.</ResponseField>
    <ResponseField name="retryable" type="Boolean!">When `true`, a retry after a short delay is safe.</ResponseField>
  </Expandable>
</ResponseField>
