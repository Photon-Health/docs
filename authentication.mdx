Every request to the Photon Network requires an `Authorization` header with a valid OAuth token. Tokens are scoped to a single account and to the permissions of the authenticated user, with the exception of machine (M2M) tokens, which have limited permissions.

## Credentials

**Application** and **Backend** credentials are used to generate **User** and **Machine** tokens, respectively.

You can find both in your [dashboard](https://app.neutron.health/settings/developers):

- **Application** credentials consist of a public `client_id` and an allowlist of URLs, which must include your application's domain.
- **Backend** credentials consist of a `client_id` and a `client_secret`. Keep the secret out of client-side code and version control.

Credentials are available in all Sandbox accounts and are a paid feature in production. If you can't access them on a paid account, contact your organization admin.

## User Token

If you're calling Network APIs from your frontend, authenticate the user via a redirect to [auth.neutron.health](https://auth.neutron.health/). Pass the resulting token in the header with each request.

User Tokens are generated with specific permissions according to the role of a logged in user. 

## Machine Token

Backend requests can be made to sync patients, draft prescriptions, and programmatically create orders.

<Info>
  Machine tokens cannot be assigned the `write:prescription` permission.
</Info>

A machine token is valid for 24 hours (`expires_in: 86400`). Request one by exchanging your `client_id` and `client_secret`:

```shellscript
curl \
  https://auth.neutron.health/oauth/token \
  --request POST \
  --header "content-type: application/json" \
  --data @- << EOF
{
  "client_id":"YOUR_CLIENT_ID",
  "client_secret":"YOUR_CLIENT_SECRET",
  "audience":"https://api.neutron.health",
  "grant_type":"client_credentials"
}
EOF
```

## Authenticate Request

All requests go to the single GraphQL endpoint:

```text
https://network.neutron.health/graphql
```

```text
Authorization: Bearer YOUR_ACCESS_TOKEN
```

Both User and Machine tokens are passed via the `Authorization` header:

```shellscript
curl --request POST \
  --url https://network.neutron.health/graphql \
  --header 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{ "query": "{ ping }" }'
```

The `ping` query is a lightweight health check. You can use it to verify your credentials.

## The `RequestMetadata` input

Every mutation in the Photon Rx API requires a `metadata` argument of type `RequestMetadata`. 

```graphql
input RequestMetadata {
  source: RequestSource!       # Required — identifies the type of caller
  sourceVersion: String        # Optional — version of your application or component
  client: String               # Optional — human-readable name of your application
  requestId: String            # Optional — caller-supplied ID for end-to-end tracing
}

enum RequestSource {
  WEB_APP                      # A browser-based web application
  EMBEDDABLE_COMPONENT         # A Photon embeddable UI widget
  DIRECT_API                   # A direct server-side API integration
  MCP_CONNECTOR                # A Model Context Protocol connector
  LLM_AGENT                    # An LLM or AI agent
}
```

<Note>
  `source` is the only required field. The remaining fields are optional but strongly recommended — `client` and `requestId` in particular make support and debugging significantly easier.
</Note>

### Field reference

<ParamField body="source" type="RequestSource" required>
  Identifies the type of system making the call. Choose the value that most accurately describes your integration. This field is used for audit logging and analytics.
</ParamField>

<ParamField body="sourceVersion" type="String">
  The version string of your application or component (e.g. `"2.4.1"`). Useful for correlating API behaviour changes with deployment events.
</ParamField>

<ParamField body="client" type="String">
  A human-readable name for your application (e.g. `"my-telehealth-app"`).
</ParamField>

<ParamField body="requestId" type="String">
  A caller-supplied identifier for this specific request (e.g. a UUID or trace ID from your own system). Use it to correlate API calls with your internal logs.
</ParamField>

### Example metadata block

```json
{
  ...
  "metadata": {
    "source": "DIRECT_API",
    "sourceVersion": "1.0.0",
    "client": "my-app",
    "requestId": "req_abc123"
  }
}
```

## Authentication errors

A missing or invalid token fails the whole request and returns a top-level `errors` array, not an `UnauthorizedError`:

```json
{ "errors": [{ "message": "An authentication token is not present", "extensions": { "code": "EMPTY_AUTHORIZATION_HEADER" } }] }
```

When the token is valid but not allowed to perform an action, the mutation returns an `UnauthorizedError` in its result union. Always include the `UnauthorizedError` fragment in your mutation selections.

```graphql
... on UnauthorizedError {
  code
  message
  requiredPermission
}
```

<ResponseField name="code" type="String">
  A machine-readable error code (e.g. `PRESCRIPTION_SIGNING_UNAUTHORIZED`). Use this field to branch your error-handling logic.
</ResponseField>

<ResponseField name="message" type="String">
  A human-readable explanation of why the request was rejected. Suitable for internal logging but not for display to end users.
</ResponseField>

<ResponseField name="requiredPermission" type="String">
  When present, indicates the specific permission scope that the calling key lacks. Use this to determine whether you need to request a different key or additional scopes from the dashboard.
</ResponseField>
