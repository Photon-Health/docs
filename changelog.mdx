Every page shows when it was last updated. This page says what's stable, and lists the changes that matter to integrators.

## What's stable

| | Status | Notes |
| --- | --- | --- |
| [Prescribe app](/prescribe/app) | Stable in Neutron | `rx.neutron.health` in the sandbox. Production, `rx.new`, is in private preview: ask your Photon contact for access. |
| [Deep links](/prescribe/app/deep-links) | Stable | No credentials needed. |
| [iframe](/prescribe/embed/iframe) | Stable | Needs your Application `client_id`, in a URL built by `frame()`. |
| [React components](/prescribe/embed/react) | Release candidate | `@photonhealth/react@rc`, currently `2.0.0-rc.1`. See [Release candidates](/prescribe/embed/release-candidates). |
| [JavaScript client](/prescribe/embed/javascript) | Release candidate | `@photonhealth/client@rc`, currently `2.0.0-rc.1`. See [Release candidates](/prescribe/embed/release-candidates). |
| [GraphQL](/network/graphql) | Available | `network.neutron.health/graphql` in the sandbox; `network.photon.health/graphql` in production. Both require a [bearer token](/authentication). |
| [Webhooks](/network/webhooks) | Stable | Signed with HMAC-SHA256. |
| [MCP](/network/mcp) | Available | Test at `ai.neutron.health` or use the [ChatGPT plugin](/network/mcp) with `ai.photon.health`. Claude is in private preview. |
| Elements | Deprecation scheduled | Will be deprecated on January 1, 2027, and fully sunset by mid-2027. See [Migrate from Elements](/prescribe/embed/migrate-from-elements). |

Durable concepts, such as [records and the send](/architecture), [permissions](/authentication#permissions) and [plans](/use-cases), change rarely. Anything marked ⚠️ or **Preview** is still moving.

## Changes

<Update label="November 13, 2026" tags={["Network", "MCP", "Prescribe"]}>
  - Production Network is available. Removed the obsolete endpoint launch warning.
  - Updated GraphQL examples for patient `contact`, `me` caller types, `routablePharmacies`, offer prices and `fulfillment.exceptions`.
  - Replaced the old sig lookup with `treatment.templates` and removed the template-application limitation.
  - Refreshed [MCP](/network/mcp) tools and client setup, with organization tools in [Admin](/network/mcp/admin).
  - Clarified that the public [SDK release candidates](/prescribe/embed/release-candidates) still use an older schema.
</Update>

<Update label="October 29, 2026" tags={["Network", "Prescribe"]}>
  **GraphQL breaking changes.** Update your queries:

  - Each payload has one [`changes`](/network/changes) list in place of `appliedChanges` and `unappliedChanges`. Each change's `status` says whether it was saved.
  - A change has `before` and `after` in place of `detail`. Options, `before` and `after` are all `Choice`s, the same type as before with a new name.
  - `UnauthorizedError` and `UpstreamServiceError` are now one [`OperationError`](/network/errors#2-result-types), with a `type` of `UNAUTHORIZED` or `UPSTREAM_SERVICE`.
  - A patient's lists are `{ status, entries }`, so you can tell "none" from "not asked". See [Reading lists](/network/patient#reading-lists).

  **New in GraphQL:**

  - Queries: [`me`](/network/graphql#me) checks a token, and [`orders`](/network/graphql#orders) lists your organization's orders. `ping` is deprecated and will be removed after January 31, 2027.
  - Orders: [`fulfillment.state`](/network/order#fulfillment) after the send, [`availablePharmacies`](/network/order#listing-pharmacies-for-an-order) through `orders`, a `reason` to [move a sent order](/network/order#moving-a-sent-order), and `near.text` to search pharmacies by place.
  - Prescriptions: [`structuredSigs`](/network/prescription#sig-options), and the assigned `prescriber`.
  - A name that matches one thing, but not exactly, now comes back `AMBIGUOUS` with `CONFIRMATION_REQUIRED`. A pharmacy search never sets the pharmacy on its own.

  **Packages:** `2.0.0-rc.1` of `@photonhealth/react` and `@photonhealth/client` is on npm. Machine credentials and sig options arrive in the next release candidate.
</Update>

<Update label="October 27, 2026" tags={["Prescribe"]}>
  - The React components and the JavaScript client are now `@photonhealth/react` and `@photonhealth/client`, published to npm as 2.0.0 release candidates under the `rc` tag. See [Release candidates](/prescribe/embed/release-candidates).
</Update>

<Update label="October 23, 2026" tags={["Network"]}>
  - [MCP](/network/mcp) stays at `ai.neutron.health` and `ai.photon.health`. It isn't moving to `network.<env>.health/mcp`, so connectors you've already set up keep working.
</Update>

<Update label="October 11, 2026" tags={["Prescribe"]}>
  - [Deep links](/prescribe/app/deep-links) and [iframe](/prescribe/embed/iframe) URLs carry Photon ids only, in plain query parameters: `patient`, `rx`, `template`, `med`, `order` and `org`. They never carry patient details. `url()` and `frame()` refuse anything that isn't an id, so sync details first and link by id.
  - Orders take a card per `rx`, `template` and `med`. A prescription takes one of them. An existing order also takes new lines: `/order/ord_ORDER_ID?rx=rx_PRESCRIPTION_ID`.
  - An id Photon doesn't have in the prescriber's organization shows **not found** on its own card. The rest of the link still opens.
  - A template becomes a prescription once the order or prescription has a patient. Until then, its card is empty.
  - Links from before this change no longer open.
</Update>

<Update label="October 11, 2026" tags={["Get started"]}>

<Update label="October 11, 2026" tags={["Prescribe", "Network"]}>

<Update label="October 9, 2026" tags={["Prescribe"]}>
  - The [iframe](/prescribe/embed/iframe) needs your Application `client_id`. Build its URL with `frame()` from the [JavaScript client](/prescribe/embed/javascript), which puts it in. A URL written by hand shows **This link can't be embedded**. Add every domain that shows the iframe, and the Prescribe app's domain, to your credential's allowed URLs.
  - Only the iframe's `/embed` pages load in another site's frame. The Prescribe app's other pages refuse.
  - [Deep links](/prescribe/app/deep-links) never carry a `client_id`, so you can share them with any prescriber.
  - Links point to the environment's Prescribe app by default, so `appUrl` is optional. `photon({ organization })` puts your organization on every link, so prescribers skip the organization picker.
  - The JavaScript client refuses a `client_secret` in a browser.
</Update>
