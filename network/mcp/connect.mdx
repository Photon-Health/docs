Use Photon in a chat app such as ChatGPT or Claude, or connect your own agent.

## Start in Neutron

1. [Create a Neutron account](https://photonhealth.com/onboard#developer).
2. Add a remote MCP connection in your client with the URL `https://ai.neutron.health`.
3. Choose OAuth sign-in and sign in with your Neutron account. Select the organization you want to work in when prompted.
4. Enable the connection in your conversation and ask it to send a prescription.

Neutron uses the same tools and prescribing workflow as production. The server instructions state that Neutron supports test prescriptions only; you do not need to say "test patient" or use special wording in your request.

Any compatible client can connect: it must support Streamable HTTP and CIMD for OAuth sign-in, or accept an existing Photon bearer token.

Try:

> Send a prescription for amlodipine to Paige Turner.

The agent uses `patient` to sync (find, create or update), `prescription` to draft/sign, `order` to draft/send, and `orders` to fetch the result. Drafting and review are built into the send flow, so you don't need to ask for a draft separately. A standalone `prescription` signing call is optional; Photon enforces signing requirements when the order is sent.

## organizations

**List your organizations and invites, or sign in to another organization.** This read-only tool is available to provider accounts. Call it with no arguments to see the current organization and the choices available to you:

```json
{}
```

The result includes `current`, `organizations`, `invites` and `nextStep`. If `current` is `null`, the other tools cannot run until you sign in to an organization.

| `nextStep` | What to do |
| --- | --- |
| `SIGNED_IN` | Continue in `current`, or choose another listed organization. |
| `SIGN_IN` | There is one organization and no pending invite. Use `signInTo.organizationId` without asking the user to choose. |
| `CHOOSE_ORGANIZATION` | Ask which listed organization to use or which invite to accept. |
| `ACCEPT_INVITE` | Open an invite's `acceptUrl` to accept it in Prescribe, then call `organizations` again. Invites cannot be accepted in chat. |
| `ONBOARD` | Open `onboardingUrl` to set up an organization, then call `organizations` again. |

To sign in to a listed organization, pass its returned ID:

```json
{ "organizationId": "org_selected" }
```

When the selected organization differs from `current`, the tool returns `SIGN_IN_REQUIRED`. Complete the Photon sign-in opened by your client and choose that organization when prompted. Keep the plugin installed; changing organizations does not require removing it. Call `organizations` again and confirm `current` before continuing. Record IDs from the previous organization may not be accessible in the new one.

Show pending invites alongside existing memberships. Preserve each returned `acceptUrl` and `onboardingUrl` exactly, including its query string, so Prescribe can return the user to their chat app. If `INVITES_UNAVAILABLE` is returned, the invite list is incomplete; do not describe it as empty.

## CIMD and client approval

**Client ID Metadata Documents (CIMD)** let an OAuth client identify itself with a hosted metadata document. Your MCP client handles this as part of connecting; clinicians don't need to configure it.

| | Neutron | Photon |
| --- | --- | --- |
| CIMD | Supported | Supported for approved clients |
| Dynamic CIMD registration | Enabled, so compatible clients can connect without prior approval | Not supported yet; clients must be approved first |
| Dynamic Client Registration (DCR) | Not supported | Not supported |

We do not plan to support DCR. Choose CIMD when building a new OAuth integration.

To whitelist a new production client, email [support@photon.health](mailto:support@photon.health) with its name, use case and CIMD metadata URL. Approval is separate from a user's access to their organization and records. A successful connection only permits the actions that their account is authorized to take.

## Use existing API credentials

Your own agent can also use a regular Photon Application or Backend client to obtain a token through your existing authentication flow. Configure its MCP transport to send that token as:

```http
Authorization: Bearer <token>
```

The public `/auth.md` on each server describes its OAuth connection flow; it does not support agent registration through the Auth.md protocol.

Use the account, token and server URL from the same environment. Keep Backend client secrets on your own server. See [Authentication](/authentication) for obtaining user and machine tokens.

A machine token can prepare drafts but cannot sign prescriptions. Hand drafts to a signed-in prescriber in [Prescribe](/integrations/agent-drafted-orders). Creating an OAuth connection for a new third-party client still follows the production approval process above.

## Connection problems

- **Client not approved:** use a supported production client or ask support to whitelist yours. For development, use Neutron.
- **`ORGANIZATION_REQUIRED`:** call `organizations` and follow its `nextStep`. Check the environment and contact your administrator or Photon support if access is blocked.
- **`VERIFICATION_REQUIRED`:** open the returned `details.verifyUrl` to complete clinician verification in Prescribe, then return and retry the same signing or submission call. Preserve the full URL, including its query string. Verification does not replace review and approval of the prescription.
- **Expired sign-in:** reconnect the client. If an earlier write had an unknown outcome, inspect the existing record before repeating it.

When contacting support, include the environment, client name and error message. Don't send access tokens or client secrets.
