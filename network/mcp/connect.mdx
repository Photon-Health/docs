Add a custom MCP connection to your chat client to try Photon in Neutron. This works in ChatGPT, Claude and other compatible clients. For production in ChatGPT, you can also use the [Photon plugin](/network/mcp).

## Start in Neutron

Use this setup to add Neutron to the chat app you already use, including ChatGPT:

1. [Create a Neutron account](https://photonhealth.com/onboard#developer).
2. In your chat client's settings, add a custom MCP server or remote connector. Name it **Neutron** and use [ai.neutron.health](https://ai.neutron.health) as the server address.
3. Choose OAuth sign-in. If the client asks how to register, choose CIMD or its published client identity.
4. Save the connection and sign in with your Neutron account. Select your organization when prompted.
5. Install or enable the connection in your conversation, then ask it to send a prescription.

In ChatGPT, open **Plugins**, select **+ → Add custom MCP server**, and use the Neutron address and OAuth settings above. Create the plugin, install it, then select it with `@` in your chat. See [ChatGPT's custom MCP setup](https://developers.openai.com/api/docs/guides/custom-mcp-server) for account and workspace requirements.

In Claude, add a custom connector from **Customize → Connectors** using the same Neutron details. See [Claude's custom connector guide](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) for individual and workspace setup.

Try:

> Send a prescription for amlodipine to Paige Turner.

Neutron uses the same prescribing workflow as production, with test prescriptions only. The assistant gathers missing details and prepares the order for your review before sending.

Use an MCP client with Streamable HTTP support. Keep the account and server in the same environment. Neutron accepts compatible OAuth clients through dynamic CIMD, or existing bearer tokens from approved integrations.

## Connect a chat client in production

To use a chat client with real patients, add a custom MCP connection using [ai.photon.health](https://ai.photon.health), choose OAuth sign-in and connect your Photon account. Enable the connection in your conversation, just as you would with Neutron.

Only **ChatGPT and Claude** are currently whitelisted for production OAuth. Claude remains in private preview and can be connected manually. To use another chat client, email [support@photon.health](mailto:support@photon.health) with the client name, use case and CIMD metadata URL. Neutron does not require this approval.

## CIMD and client approval

**Client ID Metadata Documents (CIMD)** let an OAuth client identify itself with a hosted metadata document. Your MCP client handles this as part of connecting; clinicians don't need to configure it.

| | Neutron | Photon |
| --- | --- | --- |
| CIMD | Supported | Supported for approved clients |
| Dynamic CIMD registration | Enabled, so compatible clients can connect without prior approval | Not supported yet; clients must be approved first |
| Dynamic Client Registration (DCR) | Not supported | Not supported |

We do not plan to support DCR. Choose CIMD when building a new OAuth integration.

Client approval is separate from a user's access to their organization and records. A successful connection only permits the actions that their account is authorized to take.

## Use existing API credentials

Your own agent can also use a regular Photon Application or Backend client to obtain a token through your existing authentication flow. Configure its MCP transport to send that token as:

```http
Authorization: Bearer <token>
```

The public `/auth.md` on each server describes its OAuth connection flow; it does not support agent registration through the Auth.md protocol.

Use the account, token and server URL from the same environment. Keep Backend client secrets on your own server. See [Authentication](/authentication) for obtaining user and machine tokens.

A machine token can prepare drafts but cannot sign prescriptions. Hand drafts to a signed-in prescriber in [Prescribe](/integrations/agent-drafted-orders). Creating an OAuth connection for a new third-party client still follows the production approval process above.

## Connection problems

- **Client not approved:** use a supported production client or ask support to whitelist yours. For development, use Neutron.
- **`ORGANIZATION_REQUIRED`:** follow the [organization setup steps](/network/mcp/admin#organizations). Check the environment and contact your administrator or Photon support if access is blocked.
- **`VERIFICATION_REQUIRED`:** open the returned `details.verifyUrl` to complete clinician verification in Prescribe, then return and retry the same signing or submission call. Preserve the full URL, including its query string. Verification does not replace review and approval of the prescription.
- **Expired sign-in:** reconnect the client. If an earlier write had an unknown outcome, inspect the existing record before repeating it.

When contacting support, include the environment, client name and error message. Don't send access tokens or client secrets.
