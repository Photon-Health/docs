## Start in Neutron

1. [Create a Neutron account](https://photonhealth.com/onboard#developer).
2. Add a remote MCP connection in your client with the URL `https://ai.neutron.health`.
3. Choose OAuth sign-in and sign in with your Neutron account. Select the organization you want to work in when prompted.
4. Enable the connection in your conversation and use synthetic patients to test.

Neutron creates test prescriptions only. Any compatible client can connect: it must support Streamable HTTP and CIMD for OAuth sign-in, or accept an existing Photon bearer token.

Try:

> Find test patient Paige Turner and search for amlodipine. Show me the options before completing the prescription.

The assistant uses `patient` and `prescription`, asks for unresolved details, and shows the draft for review. It must not sign or submit without the prescriber's approval.

## CIMD and client approval

**Client ID Metadata Documents (CIMD)** let an OAuth client identify itself with a hosted metadata document. Your MCP client handles this as part of connecting; clinicians don't need to configure it.

| | Neutron | Photon |
| --- | --- | --- |
| CIMD | Supported | Supported for approved clients |
| Dynamic CIMD registration | Enabled, so compatible clients can connect without prior approval | Not supported yet; clients must be approved first |
| Dynamic Client Registration (DCR) | Not supported | Not supported |

We do not plan to support DCR. Choose CIMD when building a new OAuth integration.

To whitelist a new production client, email [support@photon.health](mailto:support@photon.health) with its name, use case and CIMD metadata URL. Approval is separate from a user's access to their organization and records. A successful connection only permits the actions that their account is authorized to take.

## Use existing API credentials

Your own agent can also use a regular Photon Application or Backend client to obtain a token through your existing authentication flow. Configure its MCP transport to send that token as:

```http
Authorization: Bearer <token>
```

Use the account, token and server URL from the same environment. Keep Backend client secrets on your own server. See [Authentication](/authentication) for obtaining user and machine tokens.

A machine token can prepare drafts but cannot sign prescriptions. Hand drafts to a signed-in prescriber in [Prescribe](/integrations/agent-drafted-orders). Creating an OAuth connection for a new third-party client still follows the production approval process above.

## Connection problems

- **Client not approved:** use a supported production client or ask support to whitelist yours. For development, use Neutron.
- **No organization access:** check that you're signing into the correct environment and organization. Contact your administrator or Photon support if access is blocked.
- **Expired sign-in:** reconnect the client. If an earlier write had an unknown outcome, inspect the existing record before repeating it.

When contacting support, include the environment, client name and error message. Don't send access tokens or client secrets.
