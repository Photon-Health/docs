Photon's MCP server lets a clinician prescribe from an AI assistant like Claude or ChatGPT, and lets your own agent draft prescriptions. A session can be as short as one request:

> Prescribe amlodipine 5 mg for Paige Turner, born 1990-01-01.

The agent finds the patient, finds the medication, shows any drug interactions, and sends once the prescriber confirms.

## Get started

<Steps>
  <Step title="Create a sandbox account">
    [Sign up for Neutron](https://photonhealth.com/onboard#developer). Your account is ready right away, with no approval needed.
  </Step>
  <Step title="Add Photon to your assistant">
    Add a custom connector with the server URL `https://ai.neutron.health`. Each client's steps are below.
  </Step>
  <Step title="Sign in">
    When your assistant asks you to sign in, use your Neutron account. The assistant takes you to Photon's sign-in page and brings you back to the chat.
  </Step>
  <Step title="Try it">
    Ask your assistant to prescribe something for a test patient.
  </Step>
</Steps>

## Connect a client

<Tabs>
  <Tab title="Claude">
    1. In [claude.ai](https://claude.ai), open **Customize** in the sidebar, then **Connectors**.
    2. Click **\+**, then **Add custom connector**.
    3. Enter a name, such as `Photon Neutron`, and the remote MCP server URL `https://ai.neutron.health`.
    4. Click **Connect** and sign in with your Neutron account. The connector shows as active once you're signed in.

    Connectors you add on claude.ai also work in the Claude desktop app.

    <Tip>
      Claude can be cautious about clinical and prescribing requests. Tell it you're working in a sandbox with test patients.
    </Tip>
  </Tab>
  <Tab title="ChatGPT">
    1. In [chatgpt.com](https://chatgpt.com), open **Apps** in the sidebar, then the settings icon at the top right.
    2. Go to **Apps**, then **Advanced settings**, and click **Create app**.
    3. Enter a name, such as `Photon Neutron`, and the server URL `https://ai.neutron.health`.
    4. Sign in with your Neutron account.
    5. In a chat, turn on the app before you ask it to prescribe.
  </Tab>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http photon https://ai.neutron.health
    ```

    Then run `/mcp` in Claude Code to sign in with your Neutron account.
  </Tab>
  <Tab title="Your own agent">
    Point any MCP client that supports streamable HTTP at `https://ai.neutron.health`.

    - **To act for a prescriber**, let the client run OAuth. The server supports OAuth discovery, so a client can find the sign-in flow from the URL alone.
    - **To draft from a backend**, send a [machine token](/authentication#machine-tokens) as `Authorization: Bearer …`. A machine token can take intake, search and draft, but it can't send. A prescriber sends from [Embed](/embed/overview). See [Agent-drafted orders](/integrations/agent-drafted-orders).
  </Tab>
</Tabs>

## How it works

Prescribing is four tool calls. Each step's output feeds the next.

<Steps>
  <Step title="rx_intake: find or add the patient">
    Takes `demographic` (name, date of birth, sex, email, phone) and `clinical` (allergies, medications, diagnoses, notes). It returns a `patientId` for the rest of the session. Allergies and medications are saved on the patient and used in screening.

    If Photon can't tell which patient is meant, the call fails and says what to ask next, rather than guessing. When new safety-relevant facts come up, call it again with the `patientId`.
  </Step>
  <Step title="rx_search: find the medication">
    Takes `treatment.name` and, optionally, `treatment.strength`. It doesn't need a patient. It checks your organization's templates first (fully pre-drafted), then catalog medications, then the wider drug database. Each result is an `options[].treatment` to pass to `rx_draft` as is.
  </Step>
  <Step title="rx_draft: draft and screen">
    Takes the `patientId` and a `treatment` from `rx_search`. The treatment needs `instructions`, `dispenseQuantity` and `dispenseUnit`. If any are missing, the agent asks the clinician rather than inventing them.

    Photon screens for drug-drug and drug-allergy interactions and checks coverage. The call returns `draft.prescriptionId`, `reviewDigest` and `draft.reviewFields`, and a status of `ready`, `warning` or `blocked`. Nothing is sent at this step.
  </Step>
  <Step title="rx_send: send after the prescriber confirms">
    Takes the `patientId` and `prescriptions[]`. Each prescription carries `prescriptionId`, `reviewDigest` and `reviewedFields`, copied unchanged from the same `rx_draft` response (`reviewedFields` is that response's `draft.reviewFields`). It also takes `signed: true` and a `confirmationText`: the prescriber's own words confirming the send, quoted exactly and never written by the agent. The call returns the `orderId`.

    Photon checks that the digest and fields match what was drafted, so the prescriber sends exactly what they reviewed. It rejects blocked drafts and drafts already sent. Photon checks on the server that the token belongs to a prescriber. The agent only acts on the prescriber's behalf and is never the prescriber of record.
  </Step>
</Steps>

After an order is sent, two more tools handle fulfillment:

| Tool | Does |
| --- | --- |
| `rx_shop` | Reads an order's status, its pharmacy offers and prices, and pharmacy search results. Read-only. |
| `rx_route` | Sends the order to the pharmacy that was chosen, or reroutes it |

## Rules for agents

- **Photon decides.** When a patient or drug is ambiguous, a tool fails closed and says what to ask or send next. Agents never invent ids, instructions or quantities.
- **The agent holds the conversation.** The server keeps no state between calls. Records live in Photon, and the agent passes ids along.
- **The prescriber is the prescriber.** The agent drafts. A prescriber confirms and sends, either with `rx_send` in their own session or in [Embed](/embed/overview).
- **Neutron never sends real prescriptions.** In the sandbox, `rx_send` creates test orders only.
