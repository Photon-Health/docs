Photon's MCP server connects your clinical assistant to Network. It uses the same patients, prescriptions and orders as [Prescribe](/prescribe/overview), so you can draft in a conversation and continue reviewing in the app.

Start with what you know:

> Find test patient Paige Turner and look up amlodipine.

The assistant tries to match the patient, searches medications, and asks focused questions to complete the draft. It should search before asking for missing dosage, instructions or quantity. The prescriber reviews the result before signing or submitting an order.

## Four tools

| Tool | What it does |
| --- | --- |
| [`patient`](/network/mcp/prescribing#patient) | Finds and matches a patient, or creates and updates their demographic and clinical information. |
| [`prescription`](/network/mcp/prescribing#prescription) | Searches from a drug name or search string, progressively drafts a prescription, and signs reviewed content when requested. |
| [`order`](/network/mcp/prescribing#order) | Prepares and submits an order, or updates an explicitly chosen pharmacy. |
| [`orders`](/network/mcp/fulfillment#orders) | Reads order status and compares available pharmacies and prices without changing a record. |

The three singular tools can change records. `orders` is read-only. Search and ordinary draft edits do not sign a prescription or submit an order.

## How the workflow fits together

1. **Match the patient.** Reuse identity details from the conversation. Prefer resolving one patient and recording known clinical context before searching medications.
2. **Search, then draft.** Call `prescription` with a drug name. Include the patient when available so Photon can use recorded allergies, medication history and benefits during the prescribing workflow. You can search without a patient and attach one later.
3. **Review and finalize.** Resolve unapplied changes and review the full returned order. Confirm any draft defaults with the prescriber. Use explicit signing and submission calls after approval.
4. **Check the result.** Read the order with `orders`. Submission, pharmacy assignment and pharmacy receipt are separate milestones.

Don't ask for a pharmacy as a routine prescribing step. Only include a destination on `order` when the user explicitly specifies one. Photon handles the fulfillment link and any fallback to a saved preference.

Photon enforces permissions for every action. For an agent running on your backend, use your existing [API credentials](/authentication#machine-tokens) to prepare drafts, then hand them to a prescriber in [Prescribe](/integrations/agent-drafted-orders). Machine tokens cannot sign prescriptions.

The assistant retains the conversation and carries returned record IDs between calls. Photon stores the records. If a call returns choices or unapplied fields, resolve them and send those fields again with the appropriate ID.
